📦 Project Plan: Multi-Tenant SaaS E-commerce Platform (Shopify-like)
1️⃣ Project Overview

Build a multi-tenant SaaS e-commerce platform where multiple merchants can create and manage their own online stores.

The platform should support:

A Master Admin who controls the entire system.

Multiple Merchant Admins who manage their own stores.

Each merchant has a separate domain.

The system uses one server and one database.

Data isolation must ensure that each merchant only sees their own data.

The platform must support monthly subscription plans for merchants.

This architecture follows the Multi-Tenant (Shared Database) model used by platforms like Shopify, WooCommerce, and BigCommerce.

2️⃣ Core Architecture
Infrastructure

1 Application Server

1 Shared Database

Multiple domains

Tenant isolation using merchantId

Every data record must include:

merchantId / tenantId

This ensures proper separation of store data.

3️⃣ Roles and Permissions
👑 Master Admin

Controls the entire platform.

Permissions:

Manage merchants

Create subscription plans

View platform analytics

Suspend / activate stores

Monitor server health

View all products and orders

Track platform revenue

🏪 Merchant Admin

Controls their own store.

Permissions:

Add / edit / delete products

Manage orders

Manage customers

Manage store settings

Upload product images

View store analytics

Merchant admins must never access another merchant’s data.

👤 Customer

Permissions:

Browse store products

Add products to cart

Place orders

Manage account

Customers interact only with the merchant’s storefront.

4️⃣ Domain-Based Store Detection

Each merchant store has its own domain.

Example:

merchant1.com
merchant2.com
merchant3.com

When a request arrives at the server:

Detect the domain from the request header

domain = req.headers.host

Find the merchant linked to that domain.

Use that merchant’s merchantId to filter all data queries.

Example logic:

User visits domain1.com

Server detects domain
      ↓
Find merchant with domain1.com
      ↓
merchantId = m1
      ↓
Fetch products where merchantId = m1
      ↓
Return products

6️⃣ Subscription System

Merchants must subscribe to use the platform.

Features:

Monthly subscription plans

Automatic store deactivation if subscription expires

Upgrade / downgrade plan

Daily background job should:

Check merchant subscription expiry.

If expired → disable store.

Example logic:

if subscriptionExpireDate < today
    store.isActive = false

If the store is inactive, the storefront should show:

"Store subscription expired"
7️⃣ Product Management

When a merchant adds a product:

The system must automatically attach the merchantId.

Example product data:

{
name: "iPhone 15",
price: 1000,
merchantId: "m1"
}

When retrieving products:

fetch products where merchantId = currentMerchant

Never allow queries without merchant filtering.
